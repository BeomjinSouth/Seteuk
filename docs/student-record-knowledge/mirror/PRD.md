## 2. 제품 개요

이 프로젝트의 목표는 교육부 학생부 FAQ와 일반 Q&A를 구조화해서 두 가지 기능을 제공하는 것이다.

1. 생기부 관련 질문에 근거 기반으로 답하는 RAG 상담 챗봇
2. 사용자가 작성한 생기부 초안을 근거와 함께 점검하는 AI 리뷰

핵심은 "답변 생성"보다 "공식 근거를 우선 정리하고 재사용 가능한 지식 레이어를 만드는 것"이다.

## 3. 문제 정의

### 문제 1. 원천 정보가 게시판 단위로 흩어져 있다

- FAQ는 질문과 답변이 목록 HTML + AJAX 응답으로 분리되어 있다.
- 일반 Q&A는 페이지네이션, 답변상태, 비밀글 여부가 섞여 있다.
- 동일하거나 유사한 질문이 반복돼도 최신 기준과 대표 답변을 확인하기 어렵다.

### 문제 2. 정책형 정보와 사례형 정보가 섞여 있다

- FAQ는 비교적 정책형/정리형 답변에 가깝다.
- Q&A는 실제 사례와 맥락이 강하다.
- 두 소스를 동일한 무게로 합치면 잘못된 답변을 만들 가능성이 있다.

### 문제 3. 생기부 점검은 검색과 다른 도구가 필요하다

- 단순 검색은 "근거 찾기"까지만 해결한다.
- 실제 업무에서는 "내 문장이 이 근거에 비춰 위험한가"까지 필요하다.
- 따라서 retrieval과 review는 별도 실행 모드로 설계하되, 교사 UI에서는 하나의 작업공간 안에서 자연스럽게 오갈 수 있어야 한다.

### 문제 4. 비밀글과 연도 차이를 무시하면 위험하다

- 비밀글은 공개 본문이 없다.
- 같은 제목이라도 연도와 학교급에 따라 답변이 달라질 수 있다.
- 최신 답변 우선, 선택적 FAQ 우선, 버전 분리 규칙이 필요하다.

## 4. 제품 목표

### 제품 목표

1. FAQ/Q&A를 구조화된 canonical knowledge로 변환한다.
2. 질문 시 근거 출처를 포함한 답변을 제공한다.
3. 생기부 초안 점검 시 위험 항목, 근거, 수정 방향을 함께 제공하고, 세특 작성 탭에서 근거 제한 개선본을 원클릭으로 생성한다.
4. 운영자가 재수집/재인덱싱/품질 점검을 할 수 있게 만든다.

### 운영 목표

1. 반복 문의 대응 시간을 줄인다.
2. FAQ/Q&A 활용률을 높인다.
3. 생기부 검토 시 수작업 탐색 시간을 줄인다.

## 7. 데이터 우선순위 정책

답변 생성과 점검 모두 아래 우선순위를 따른다.

1. 기재요령/훈령/법령
2. 학생부 FAQ
3. 공개 Q&A

세부 규칙:

- FAQ는 정책형 대표 근거로 우선 사용한다.
- Q&A는 사례형 보조 근거로 사용한다.
- 비밀글은 통계/운영 메타데이터만 사용하고 답변 근거에는 넣지 않는다.
- 동일 질문에 다른 답변이 있으면 연도, 학교급, 출처 우선순위를 같이 보여준다.

## 8. 핵심 사용자 시나리오

### 시나리오 A. RAG 상담

1. 사용자가 `AI 세특 생성` 작업공간의 사이드바에서 `학생부 상담·점검` 탭 선택
2. 작업공간 안에서 `질문 답변` 모드 선택
3. 질문 입력
4. 시스템이 학교급/영역/연도 조건을 해석
5. 관련 FAQ/Q&A/정책 근거 검색
6. 모델이 근거 기반 답변 생성
7. 답변과 함께 출처, 주의사항, 상충 여부 표시

### 시나리오 B. 생기부 점검

1. 사용자가 `AI 세특 생성` 작업공간의 사이드바에서 `학생부 상담·점검` 탭 선택
2. 작업공간 안에서 `문구 점검` 모드 선택
3. 초안 텍스트 입력
4. 시스템이 텍스트를 문장 단위로 분해
5. 관련 정책/FAQ/Q&A 근거 검색
6. 위험 항목, 이유, 근거, 수정 방향 생성
7. 사용자가 수동으로 수정하거나 세특 작성 탭에서 점검·개선 버튼으로 개선본을 생성

### 시나리오 C. 운영/관리

1. 운영자가 재수집 실행
2. 변경된 지식과 실패 문서 확인
3. canonical 지식 재생성
4. 검색 인덱스 재구축

### 시나리오 D. 교사별 수업 맥락 관리

1. 교사가 `학교=성호중학교`, `아이디=본인 한글 이름`, `비밀번호=123123`으로 로그인
2. 로그인 성공 시 학생 관리 화면으로 이동
3. 2026 성호중학교 1/2/3학년 공용 명렬표를 자동으로 불러옴
4. 교사는 자신이 실제로 수업하는 여러 학급만 "담당 수업"으로 연결
5. 각 수업 학급별로 학생 관찰 메모를 수동 또는 OCR 기반으로 기록
6. 세특 AI 작성 시 같은 교사/같은 학급의 기록만 컨텍스트로 사용

### 시나리오 E. 학생 개별 데이터와 쿠키 운영

- 별도 상단 `학생 데이터` 탭과 `/student-data` 화면은 현재 사용자 흐름에서 제거한다.
- 교사 작업공간은 학생 명부/담당 학급 연결, 관찰 기록, 세특 작성 흐름에 집중한다.
- 세특 생성은 관찰 메모, 학생 관찰 기록 활동판의 차시별 △/○ 기록을 해석한 멘토·멘티 활동 요약, 학습 데이터, OCR 평가 컨텍스트를 사용하며 별도 학생 데이터 탭 입력값을 조회하지 않는다.
- `학생 관찰 기록` 멘토·멘티 활동판의 차시별 상태는 빈칸 0개, △ 참여함 1개, ○ 매우 잘함 2개 규칙으로 쿠키 원장에 자동 반영하고, 상태를 수정하면 이전 상태와 새 상태의 차액만 기록한다.

- rewrite guidance
- 세특 작성 탭 원클릭 점검·개선
- 선택 학생 간 문장 단위 유사도 경고

## 9.6 교사 작업공간

- 성호중학교 전용 로그인: 학교명 `성호중학교`, 아이디는 교사 본인 한글 이름, 비밀번호 `123123`
- 성호중학교 교사는 2026 명렬표 기반 공용 명부에서 학급만 선택해 등록
- 학교 전체 학생 명부 업로드
- 교사별 담당 학급 매핑
- 학생 관리: 학교 전체 명부 업로드 + 교사별 담당 학급 연결
- 학생 관찰 기록: `/observation-board-2` 기반 교실 대시보드 + 관찰 메모 작성 흐름
- 상단 주요 탭 순서: 학교 정보 → 학생 관찰 기록 → AI 세특 생성 → 평가 점검
- 평가 점검은 탭에 `평가 점검 (개발중)`으로 보이지만 현재 접근 차단 상태이며, 직접 `/eval-check`로 들어오면 `/dashboard`로 이동한다.
- 학습지 OCR은 `/ocr` 경로와 기능 코드를 유지하되, 현재는 상단 탭에서 숨김 처리한다.
- `학생 관찰 기록`은 `/observation-board-2`에서 예시 PNG에 맞춘 독립형 교실 대시보드를 제공하고, 기본 진입 화면은 내부 탭이나 가로로 긴 학급 칩 나열 없이 `학생 관찰 기록` 멘토·멘티 활동판으로 고정한다.
- `학생 관찰 기록`의 기본 멘토·멘티 화면은 전체 담당 학급 합산 보기 대신 담당 학급 하나를 단일 선택 메뉴로 골라 학급별 학생만 표시해야 한다.
- `학생 관찰 기록`의 왼쪽 메뉴는 외부 링크가 아니라 `학생 관찰 기록`, `성장 기록`, `통계 보기`, `알림장`, `설정` 내부 화면 전환 버튼으로 동작해야 하며, 좁은 창에서도 기준 PNG처럼 왼쪽 세로 사이드바로 유지해야 한다.
- `학생 관찰 기록`의 기본 화면은 멘토·멘티 구성, 모둠 추가, 차시별 △/○ 활동 기록표, 하단 활동 기록 안내를 첫 화면에서 제공하고, 학생 목록/조가 늘어나면 패널 내부 스크롤로 처리해야 한다.
- `학생 관찰 기록`의 차시별 활동 기록표는 각 차시의 날짜와 활동 내용을 교사가 표 헤더에서 직접 입력할 수 있어야 하며, `+` 버튼으로 새 차시를 추가할 수 있어야 한다.
- `학생 관찰 기록`의 차시별 활동 기록표에서 학생 상태를 빈칸/△/○로 바꾸면 빈칸 0개, △ 1개, ○ 2개 기준의 쿠키 차액이 해당 학생 쿠키 원장에 자동 반영되어야 한다.
- `학생 관찰 기록`은 실제 담당 학급 학생만 멘토·멘티, 관찰 작성, 성장 기록, 통계에 표시해야 하며 담당 학급 학생이 없을 때 샘플 학생으로 대체하지 않는다.
- `학생 관찰 기록`의 `성장 기록`은 기존 관찰 기록을 학생별 누적 타임라인으로 표시하고, 학생별 관찰 공백/최근 메모/△·○ 반응을 함께 보여주며, 같은 탭 안에서 선택 학생 대상의 `성장 기록 작성` 모달로 관찰 메모를 남길 수 있어야 한다.
- `학생 관찰 기록`의 `성장 기록` 학생 카드에는 성장 기록 쿠키 태그와 현재 차시별 △/○ 표시 기준으로 계산한 학생별 쿠키 수를 함께 보여준다.
- `성장 기록 작성` 모달은 제공된 기준 이미지처럼 배경을 흐리게 덮은 중앙 3단계 작성 흐름으로 표시하고, 선택 학생 동물 칩, 쿠키 1~3개 선택 카드, 선택 메모 입력, `이전`/`저장하기` 하단 버튼을 같은 화면에서 제공한다.
- `학생 관찰 기록`의 `통계 보기`는 관찰 기록 수, 학생별 기록 수, 태그 빈도, 최근 기록일, 현재 세션의 △/○ 개수, 기록 우선 학생, 모둠별 활동 균형을 카드와 간단한 막대형 차트로 제공해야 한다.
- `학생 관찰 기록`의 `통계 보기`는 전체 담당 학급 합산을 기본으로 펼치지 않고, compact 학급 선택 메뉴로 담당 학급 하나씩 전환해 볼 수 있어야 한다.
- `학생 관찰 기록`의 `알림장`은 서버 API 없이 교사별 localStorage에 공지 작성/목록/완료 상태를 저장해야 한다.
- 기존 관찰 메모 작성 기능은 기본 화면을 방해하지 않도록 사이드바에서 별도 항목으로 노출하지 않고 `성장 기록` 탭의 작성 모달 또는 `설정` 보조 버튼으로 접근한다.
- `학생 관찰 기록`의 기본 화면은 제공된 Maplestory TTF를 사용해야 하며, 멘토·멘티 카드 또는 학생 목록에서 학생 이름을 드래그해 멘토/멘티 역할과 조 배치를 바꾸고 빈 모둠을 추가할 수 있어야 한다.
- 기존 `/observation-board`와 `/observations` 직접 진입은 새 `학생 관찰 기록` 화면인 `/observation-board-2`로 이동시킨다.
- 수업별 관찰 메모 저장
- 수동 관찰 기록 작성: 상단 공통 맥락에서 `날짜`, `수업 주제`, 공통 태그를 입력하고, 학생별 행에서는 개별 태그와 `관찰 메모` 중심으로 빠르게 입력
- 수업 메모와 세특 초안의 컨텍스트 연동
- 세특 유사도 검사는 서로 다른 학생 사이에서 90% 이상 동일한 문장만 결과로 보여준다.
- 역량 분석은 세특 원문 기준으로 지식·과정·태도 구간을 색상 밑줄로 표시하고, 원문 누락 없이 분석 필요/완료 상태를 보여준다.
- 세특 작성 탭은 제공된 AI 세특 작성기 화면 기준으로 상단 교사/알림 영역, AI 세특 생성 사이드바, 반 선택 칩, 작업 버튼, 10명 단위 페이지네이션, AI 입력 데이터/세특 내용 프롬프트형 테이블을 제공한다.
- 세특 생성 참고 데이터는 관찰 메모, 학생 관찰 기록 활동판의 차시별 △/○ 기록을 해석한 멘토·멘티 활동 요약, 학습 데이터, OCR 평가 컨텍스트로 제한하고 별도 학생 데이터 탭 입력값은 사용하지 않는다.
- 세특 작성 기본 시스템 프롬프트는 `strict-observation-v1`로 운영하며, 제공된 관찰 데이터만 근거로 삼고 점수/등수/수상/시험 문항/학생 수준 직접 표현을 배제하는 교사 관찰 기록 작성 원칙을 따른다.
- AI 설정 화면은 모든 교사가 `기본 설정`과 `내 프롬프트` 중 하나를 선택하게 하며, `기본 설정`은 읽기 전용 `strict-observation-v1`, `내 프롬프트`는 본인 계정에서만 사용하는 개인 프롬프트로 저장한다.
- 모델, max output tokens, reasoning effort는 관리자 전용 설정으로 유지한다.
- 관리자 권한은 성호중학교 내부 기존 관리자만 `/settings`에서 교사 이름으로 추가/해제할 수 있고, 최초 관리자 `박범진`은 잠금 방지를 위해 해제할 수 없다.
- 운영 배포 저장소는 Supabase-only로 고정하며, Supabase 환경변수가 없으면 저장 API는 명확한 503 오류를 반환한다. Google Sheets는 로컬 개발 fallback과 명렬표 import/migration 보조 경로로만 둔다.
- 금지어 기본 목록은 과장 표현, 서열/점수 표현, 부정 낙인, 미래 예측, 직접 조언 표현을 포함하고, store와 `/api/forbidden`에서 같은 공통 목록을 사용한다.

## 10. 기능 요구사항

### FR-1. 수집

- 연도별 Q&A 수집 가능
- 마지막 페이지 자동 탐지
- 원본 응답 캐시 저장
- 비밀글은 접근불가 문서로 분리

### FR-2. 정규화

- 질문/답변/근거를 분리한다.
- 메타데이터를 표준값으로 맞춘다.
- 원문을 요약해 덮어쓰지 않는다.

### FR-3. 중복 통합

- 동일 질문은 묶는다.
- 띄어쓰기, `(재상담)` 접두어, 일반 문의 꼬리 표현만 다른 질문은 보수적 질문 그룹 키로 묶는다.
- 동일 질문 + 다른 답변은 versioned knowledge로 남긴다.
- 학교급/연도 차이를 무시하고 강제 통합하지 않는다.

### FR-4. 상담 챗봇

- 답변마다 1개 이상의 출처를 표시한다.
- 비밀글 직접 인용 금지
- 연도/학교급 차이 노출
- FAQ/정책 우선

### FR-5. 생기부 점검

- 위험 항목별 이유를 보여준다.
- 근거 없는 자동 수정 금지
- rewrite guidance는 방향 제시 수준으로 제공한다.
- 세특 작성 탭에서는 점검 결과와 동일한 공개 근거를 사용해 개선본을 생성할 수 있어야 한다.
- 개선본은 원문과 공개 근거에 없는 사실을 추가하지 않아야 한다.
- 유사도 검사는 세특 전체 유사도가 아니라 문장 단위로 수행하고, 다른 학생 사이에 90% 이상 동일한 문장만 표시한다.
- 확실하지 않으면 수동 확인 필요로 표시한다.

#### OpenAI 모델 운영 기준

- 평가 점검, 학습지 OCR, 루브릭 추출, 예비 채점, 모범답안 생성, 세특 생성/점검에 사용하는 OpenAI 기본 모델은 `gpt-5.4-mini`로 통일한다.
- 이미지 입력이 필요한 흐름은 OpenAI Responses API의 `input_image` 형식을 사용한다.
- 비전 입력 세부도는 `gpt-5.4-mini`에서 지원하는 범위(`low`, `high`, `auto`) 안에서 운영하며, 문항 판독과 루브릭 추출 기본값은 `detail: "high"`로 둔다.

### FR-6. 운영

- `/api/admin/crawl`에서 `--refreshCache` 기반 재수집 실행 가능
- `/api/admin/crawl-status`에서 최신 산출 통계 확인 가능
- `/api/admin/quality-report`에서 canonical/knowledge unit 품질 리포트 생성 가능
- `/api/admin/reindex`에서 hosted vector store 재인덱싱 가능
- 배포 환경의 운영 API는 `ADMIN_API_TOKEN`으로 보호되어야 함
- 실패 문서 재처리는 이후 운영 UI 단계에서 보완

### FR-7. 교사별 담당 학급과 세특 컨텍스트

- 학생 명부는 학적 기준으로 1회 업로드하고, 교사 로그인 후 담당 학급만 별도로 연결할 수 있어야 한다.
- 성호중학교 계정은 지정된 학교명/한글 이름/비밀번호 조합일 때만 로그인 성공해야 한다.
- 성호중학교 교사는 별도 업로드 없이 2026 공용 명렬표에서 담당 학급을 선택 등록할 수 있어야 한다.
- 학교 전체 명부는 학교 단위 공용 데이터로 저장되어 같은 학교 다른 사용자가 접속해도 기존 업로드 결과를 바로 불러올 수 있어야 한다.
- 학교 전체 명부를 다시 업로드할 때 기존 공용 명부와 겹치는 학생은 학적 키 기준으로 자동 중복 제거하고, 달라진 학적 정보만 갱신해야 한다.
- 관찰 메모와 세특 초안은 `교사-과목-학급` 단위로 분리 저장되어야 한다.
- 세특 AI 생성 시 다른 교사/다른 과목 메모를 섞지 않고 현재 수업 맥락의 기록만 사용해야 한다.
- 세특 AI 생성 시 `/observation-board-2`의 차시별 활동판에서 교사가 남긴 △ 참여함 / ○ 매우 잘함 표시는 같은 교사 컨텍스트의 학생별 참고자료로 사용하되, 차시별 표시를 그대로 나열하지 않고 성실성, 활동 지속성, 관계 참여, 역할 수행, 성장 흐름으로 해석해 사용해야 한다.
- 세특 AI 생성 시 기본 시스템 프롬프트는 교사 관찰 기록 작성 원칙을 우선 적용하고, 교육과정과 OCR 평가 컨텍스트는 관찰 근거와 연결되는 경우에만 활용해야 한다.
- 수업 기록은 OCR 저장뿐 아니라 수동 입력도 가능해야 한다.
- 학생 카드에서 여러 학생을 선택한 뒤 선택된 카드 더블클릭만으로 같은 수업 학급 학생들의 관찰 기록을 일괄 작성할 수 있어야 한다.
- 수동 관찰 기록 UI는 평가 과제/근거 유형 자유 입력 대신 학생별 행 편집과 선택형 태그를 기본 입력 방식으로 사용해야 한다.
- 수동 관찰 기록 UI는 기록 대상 선택 뒤 중복되는 학반 메타 필드를 다시 입력하지 않도록 최소 입력만 남기고, 공통 태그와 학생별 개별 태그 모두 버튼 클릭과 교사 직접 추가를 함께 지원해야 한다.
- 별도 `학생 데이터` 상단 탭, 성적/멘토링 입력 화면, 쿠키 원장/상품 관리 화면은 현재 제공하지 않는다.
