## 2. 제품 개요

이 프로젝트의 목표는 교육부 학생부 FAQ와 일반 Q&A를 구조화해서 두 가지 기능을 제공하는 것이다.

1. 생기부 관련 질문에 근거 기반으로 답하는 RAG 상담 챗봇
2. 사용자가 작성한 생기부 초안을 근거와 함께 점검하는 AI 리뷰

핵심은 "답변 생성"보다 "공식 근거를 우선 정리하고 재사용 가능한 지식 레이어를 만드는 것"이다.

## 3. 문제 정의

### 문제 1. 원천 정보가 게시판 단위로 흩어져 있다

- FAQ는 질문과 답변이 목록 HTML + AJAX 응답으로 분리되어 있다.
- 일반 Q&A는 페이지네이션, 답변상태, 비밀글 여부가 섞여 있다.
- 동일하거나 유사한 질문이 반복돼도 최신 기준과 대표 답변을 확인하기 어렵다.

### 문제 2. 정책형 정보와 사례형 정보가 섞여 있다

- FAQ는 비교적 정책형/정리형 답변에 가깝다.
- Q&A는 실제 사례와 맥락이 강하다.
- 두 소스를 동일한 무게로 합치면 잘못된 답변을 만들 가능성이 있다.

### 문제 3. 생기부 점검은 검색과 다른 도구가 필요하다

- 단순 검색은 "근거 찾기"까지만 해결한다.
- 실제 업무에서는 "내 문장이 이 근거에 비춰 위험한가"까지 필요하다.
- 따라서 retrieval과 review는 별도 기능으로 설계해야 한다.

### 문제 4. 비밀글과 연도 차이를 무시하면 위험하다

- 비밀글은 공개 본문이 없다.
- 같은 제목이라도 연도와 학교급에 따라 답변이 달라질 수 있다.
- 최신 답변 우선, 선택적 FAQ 우선, 버전 분리 규칙이 필요하다.

## 4. 제품 목표

### 제품 목표

1. FAQ/Q&A를 구조화된 canonical knowledge로 변환한다.
2. 질문 시 근거 출처를 포함한 답변을 제공한다.
3. 생기부 초안 점검 시 위험 항목, 근거, 수정 방향을 함께 제공하고, 세특 작성 탭에서 근거 제한 개선본을 원클릭으로 생성한다.
4. 운영자가 재수집/재인덱싱/품질 점검을 할 수 있게 만든다.

### 운영 목표

1. 반복 문의 대응 시간을 줄인다.
2. FAQ/Q&A 활용률을 높인다.
3. 생기부 검토 시 수작업 탐색 시간을 줄인다.

### 2차 사용자

- 학교 관리자

## 7. 데이터 우선순위 정책

답변 생성과 점검 모두 아래 우선순위를 따른다.

1. 기재요령/훈령/법령
2. 학생부 FAQ
3. 공개 Q&A

세부 규칙:

- FAQ는 정책형 대표 근거로 우선 사용한다.
- Q&A는 사례형 보조 근거로 사용한다.
- 비밀글은 통계/운영 메타데이터만 사용하고 답변 근거에는 넣지 않는다.
- 동일 질문에 다른 답변이 있으면 연도, 학교급, 출처 우선순위를 같이 보여준다.

## 8. 핵심 사용자 시나리오

### 시나리오 A. RAG 상담

1. 사용자가 `AI 세특 생성` 작업공간의 사이드바에서 `학생부 상담` 탭 선택
2. 질문 입력
3. 시스템이 학교급/영역/연도 조건을 해석
4. 관련 FAQ/Q&A/정책 근거 검색
5. 모델이 근거 기반 답변 생성
6. 답변과 함께 출처, 주의사항, 상충 여부 표시

### 시나리오 B. 생기부 점검

1. 사용자가 `AI 세특 생성` 작업공간의 사이드바에서 `생기부 점검` 탭 선택
2. 초안 텍스트 입력
3. 시스템이 텍스트를 문장 단위로 분해
4. 관련 정책/FAQ/Q&A 근거 검색
5. 위험 항목, 이유, 근거, 수정 방향 생성
6. 사용자가 수동으로 수정하거나 세특 작성 탭에서 점검·개선 버튼으로 개선본을 생성

### 시나리오 C. 운영/관리

1. 운영자가 재수집 실행
2. 변경된 지식과 실패 문서 확인
3. canonical 지식 재생성
4. 검색 인덱스 재구축

### 시나리오 D. 교사별 수업 맥락 관리

1. 교사가 학교명/이름/과목으로 로그인
2. 필요하면 데모 체험 버튼으로 샘플 작업공간을 즉시 생성
3. 학교 전체 학생 명부를 엑셀로 업로드하거나 기존 명부를 불러옴
4. 교사는 자신이 실제로 수업하는 여러 학급만 "담당 수업"으로 연결
5. 각 수업 학급별로 학생 관찰 메모를 수동 또는 OCR 기반으로 기록
6. 세특 AI 작성 시 같은 교사/같은 과목/같은 학급의 기록만 컨텍스트로 사용

## 9. 기능 범위

## 9.1 수집기

- FAQ 전체 수집
- 일반 Q&A 전체 수집
- 마지막 페이지 자동 탐지
- 비밀글 자동 분기
- 캐시 저장
- Markdown/JSON 생성

## 9.2 지식 정규화

- 제목/본문/답변/근거 분리
- 학교급/구분 정규화
- 중복 질문 판단
- 버전 분리
- source map 저장
- knowledge unit 산출
- policy anchor 추출

## 9.3 RAG 상담 챗봇

- `AI 세특 생성` 작업공간 내부 사이드바 탭 제공
- 학교급/구분/연도 필터
- citation 포함 답변
- 상충 답변 요약
- 확실하지 않은 경우 경고

## 9.4 생기부 점검 AI

- `AI 세특 생성` 작업공간 내부 사이드바 탭 제공
- 영역별 위험 탐지
- 근거 기반 issue list
- rewrite guidance
- 세특 작성 탭 원클릭 점검·개선
- 선택 학생 간 문장 단위 유사도 경고
- high / medium / low 위험도

## 9.5 운영 도구

- 재수집
- 재인덱싱
- 실패 문서 재처리
- 품질 점검 리포트

## 9.6 교사 작업공간

- 학교 전체 학생 명부 업로드
- 교사별 담당 학급 매핑
- 학생 관리: 학교 전체 명부 업로드 + 교사별 담당 학급 연결
- 학생 관찰 기록: 학생 카드 보드 + 관찰 메모
- 상단 주요 탭 순서: 학교 정보 → 학생 관찰 기록 → AI 세특 생성 → 평가 점검 → 학습지 OCR
- 학생 카드 보드: 클릭으로 학생 선택, 더블클릭으로 관찰 기록 작성 진입
- 수업별 관찰 메모 저장
- 수업 메모와 세특 초안의 컨텍스트 연동
- 세특 유사도 검사는 서로 다른 학생 사이에서 90% 이상 동일한 문장만 결과로 보여준다.

## 10. 기능 요구사항

### FR-1. 수집

- 연도별 Q&A 수집 가능
- 마지막 페이지 자동 탐지
- 원본 응답 캐시 저장
- 비밀글은 접근불가 문서로 분리

### FR-2. 정규화

- 질문/답변/근거를 분리한다.
- 메타데이터를 표준값으로 맞춘다.
- 원문을 요약해 덮어쓰지 않는다.

### FR-3. 중복 통합

- 동일 질문은 묶는다.
- 동일 질문 + 다른 답변은 versioned knowledge로 남긴다.
- 학교급/연도 차이를 무시하고 강제 통합하지 않는다.

### FR-4. 상담 챗봇

- 답변마다 1개 이상의 출처를 표시한다.
- 비밀글 직접 인용 금지
- 연도/학교급 차이 노출
- FAQ/정책 우선

### FR-5. 생기부 점검

- 위험 항목별 이유를 보여준다.
- 근거 없는 자동 수정 금지
- rewrite guidance는 방향 제시 수준으로 제공한다.
- 세특 작성 탭에서는 점검 결과와 동일한 공개 근거를 사용해 개선본을 생성할 수 있어야 한다.
- 개선본은 원문과 공개 근거에 없는 사실을 추가하지 않아야 한다.
- 유사도 검사는 세특 전체 유사도가 아니라 문장 단위로 수행하고, 다른 학생 사이에 90% 이상 동일한 문장만 표시한다.
- 확실하지 않으면 수동 확인 필요로 표시한다.

### FR-6. 운영

- 재수집 실행 가능
- 품질 리포트 생성 가능
- 실패 문서 재처리 가능

### FR-7. 교사별 담당 학급과 세특 컨텍스트

- 학생 명부는 학적 기준으로 1회 업로드하고, 교사 로그인 후 담당 학급만 별도로 연결할 수 있어야 한다.
- 관찰 메모와 세특 초안은 `교사-과목-학급` 단위로 분리 저장되어야 한다.
- 세특 AI 생성 시 다른 교사/다른 과목 메모를 섞지 않고 현재 수업 맥락의 기록만 사용해야 한다.
- 수업 기록은 OCR 저장뿐 아니라 수동 입력도 가능해야 한다.
- 학생 카드에서 여러 학생을 선택한 뒤 선택된 카드 더블클릭만으로 같은 수업 학급 학생들의 관찰 기록을 일괄 작성할 수 있어야 한다.
