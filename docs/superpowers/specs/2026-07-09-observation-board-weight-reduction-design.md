# 짝모둠(멘토·멘티) 활동 반영 완화 설계

작성일: 2026-07-09
대상 브랜치: codex/math-concept-hierarchy

## 문제

짝모둠(멘토·멘티) 활동판 기록을 바탕으로 세특을 생성하면, 다음과 같이 활동판 데이터를 거의 그대로 풀어쓴 문장만 반복해서 나온다.

> 서로 알아가기 멘토 활동에서 11조 멘토로 참여하여 관계 형성 활동의 진행에 맞추어 함께 활동함.

교사는 세특을 기본적으로 세특 시스템 프롬프트(교과 내용·관찰 근거 중심 서술 규칙)를 근거로 작성하고, 짝모둠 활동은 "간단히 참고하는 정도"로만 반영되기를 원한다. 조 번호·역할·활동명이 문장의 중심 소재가 되는 지금 동작은 과도한 반영이다.

## 원인

두 지점이 겹쳐 활동판 데이터가 과대 반영된다.

1. **시스템 프롬프트 `[핵심 목표]`** (`src/lib/prompts/seteuk.ts:56`)
   "학생별 관찰 근거가 짧더라도 … 축소하지 않는다"는 지시가 근거의 종류를 구분하지 않아, 멘토·멘티 활동 해석(우선순위 3)까지 이 규칙의 적용 대상으로 읽힌다. 상위 근거(관찰 메모·학습 데이터)가 전혀 없어도 모델이 활동판 기록을 최대한 살려 서술하게 된다.

2. **route.ts 삽입 지시문** (`src/app/api/generate/route.ts:279`)
   `[멘토·멘티 활동 해석]` 섹션에 "관계 기반 활동에서 드러난 … 성장 흐름으로 자연스럽게 반영하세요"라고 지시한다. "자연스럽게 반영"은 활동판이 유일한 소재일 때도 적극 활용하라는 신호로 작동한다.

## 결정 (사용자 확정: 2026-07-09)

**"거의 배제"** 방향으로 완화한다.

- 관찰 메모·학습 데이터(우선순위 1~2)가 **하나라도 있으면**: 기존대로 활동판 해석을 태도(성실성·책임감·협력 등)를 뒷받침하는 짧은 보조 근거로만 사용한다.
- 관찰 메모·학습 데이터가 **전혀 없으면**: 조 번호, 역할(멘토/멘티/n조), 활동명("서로 알아가기", "관계 형성" 등), 차시 구체 정보를 문장에 쓰지 않는다. 일반적인 수업 참여 태도 문장으로만 짧게 서술한다.

## 변경 범위

기본 프롬프트 규칙과 생성 직전 활동판 context 직렬화를 함께 수정한다. localStorage 스키마와 클라이언트 payload 타입은 유지한다. 개인 프롬프트 본문은 수정하지 않지만, 조·역할·활동명·차시 상세를 제거하는 전역 근거 최소화 정책은 기본/개인 프롬프트와 단일/일괄 생성 모두에 적용한다.

### 변경 1: `src/lib/prompts/seteuk.ts`

- `[핵심 목표]` (56행): "근거가 짧더라도 축소하지 않는다" 규칙이 **관찰 메모·학습 데이터·수행 결과**에만 적용됨을 명시한다. 멘토·멘티 활동 해석은 이 규칙의 확장 대상이 아님을 덧붙인다.
- `[근거 우선순위]` (58~68행): 3순위(멘토·멘티 활동 해석)에 대해, 상위 근거(1~2순위)가 없을 때는 그 자체로 문장의 중심 소재가 될 수 없으며, 조·역할·활동명 같은 구체 표현 대신 일반적인 수업 참여 태도 문장으로 대체한다는 규칙을 추가한다.
- 버전 문자열 `SETEUK_DEFAULT_SYSTEM_PROMPT_VERSION`을 `cross-curricular-seteuk-v2.4` → `v2.5`로 올린다(프롬프트 캐시·추적 일관성).

### 변경 2: 단일·일괄 생성 route

- `/api/generate`와 `/api/generate-batch`가 모두 관찰 메모와 학습 데이터 존재 여부를 공통 포맷터에 전달한다.
- route는 포맷터가 만든 축약 context만 추가하고, 활동판 원문이나 서로 다른 지시문을 중복 조립하지 않는다.
### 변경 3: `src/lib/observation-board-ai-context.ts`

- AI 프롬프트로 보내기 전에 조 번호, 역할명, 활동명, 날짜, 차시별 주제와 △/○ 원문을 제거한다.
- 관찰 메모 또는 의미 있는 학습 데이터가 있으면 짧은 태도 보조 근거로, 둘 다 없으면 일반적인 수업 참여 태도 한 문장으로만 사용할 수 있는 축약 context를 만든다.

### 변경 4: `/api/generate-batch`와 회귀 테스트

- 두 명 이상 생성에서도 단일 생성과 같은 포맷터와 근거 판정을 사용한다.
- `tests/observation-board-ai-context.test.mjs`에서 활동판 단독, 관찰 메모 동반, 공백 학습 데이터 케이스를 검증한다.

## 검증

관찰 메모·학습 데이터 없이 짝모둠 활동판 기록만 있는 케이스를 만들어 `/api/generate`를 직접 호출하고, 실제 출력에 다음이 없는지 확인한다.

- 조 번호(예: "11조")
- 역할 명칭("멘토", "멘티")
- 활동명("서로 알아가기", "관계 형성" 등)

대신 일반적인 수업 참여 태도 문장이 나오는지 확인한다. 관찰 메모가 있는 케이스도 함께 호출해 기존 동작(태도 보조 근거로 반영)이 유지되는지 회귀 확인한다.

검증 4종 세트(lint·typecheck·build·test)는 프롬프트 규칙과 입력 직렬화 변경이므로, 리팩토링 로드맵 규칙에 따라 실행한다.
