## 1. 프로젝트 배경

Seteuk은 한국 중등 교사용 세특(교과 세부능력 및 특기사항) 초안 생성 웹앱(Next.js 16, App Router, TypeScript, OpenAI Responses API)이다. 교사가 학생별 자료를 입력하면 학교생활기록부 문체의 세특 초안을 만들어 준다.

입력 근거는 여러 종류가 있고, 시스템 프롬프트에 **근거 우선순위**가 정의되어 있다.

1. 교사 관찰 메모와 수행 과정 기록
2. 학생별 입력 자료, 수업 중 작성·발표·토의·질문·산출물 내용
3. 멘토·멘티(짝모둠) 활동 해석 — 교사가 차시별 활동판에 남긴 △/○ 기록을 요약한 것
4. OCR 피드백(점수·등급 제외)
5. 선택 단원 context, 교육과정, 학년·교과 힌트

이 중 **3순위 "멘토·멘티 활동 해석"**이 이번 작업의 대상이다. 짝모둠 활동판 데이터는 별도 입력 필드가 아니라 클라이언트 localStorage에서 읽어 `observationBoardContext`로 API에 전달된다.

---

## 2. 사용자 요청 (원문 의도)

짝모둠 활동 기록을 바탕으로 세특을 생성하면 아래처럼 **활동판 데이터를 거의 그대로 풀어쓴 문장**만 반복해서 나온다:

> 서로 알아가기 멘토 활동에서 11조 멘토로 참여하여 관계 형성 활동의 진행에 맞추어 함께 활동함.

사용자(교사)의 의도:
- 세특은 **기본적으로 세특 시스템 프롬프트(교과 내용·관찰 근거 중심 서술 규칙)를 근거로** 작성되어야 한다.
- 짝모둠 활동 내용은 **"간단히 참고하는 정도"**로만 반영되면 좋겠다. 적당히 반영되거나, 활동판과 연관성이 약하게 나와도 괜찮다.
- 조 번호·역할·활동명이 문장의 중심 소재가 되는 지금 동작은 과도하다.

**확정된 방향 (사용자 확인 완료): "거의 배제".**
- 관찰 메모·학습 데이터(1~2순위)가 **하나라도 있으면**: 기존대로 활동판 해석을 태도(성실성·책임감·협력 등)를 뒷받침하는 **짧은 보조 근거로만** 사용.
- 관찰 메모·학습 데이터가 **전혀 없으면**: 조 번호, 역할("멘토"/"멘티"/"n조"), 활동명("서로 알아가기"/"관계 형성" 등), 차시 구체 정보를 **최종 문장에 쓰지 않는다.** 일반적인 수업 참여 태도 문장으로만 짧게 서술.

## 3. 원인 진단

두 지점이 겹쳐 활동판 데이터가 과대 반영된다.

**(1) 시스템 프롬프트 `[핵심 목표]`** — `src/lib/prompts/seteuk.ts:54-56`
"학생별 관찰 근거가 짧더라도 … 축소하지 않는다"는 지시가 근거의 종류를 구분하지 않아, 멘토·멘티 활동 해석(3순위)까지 이 규칙의 적용 대상으로 읽힌다. 상위 근거가 없어도 모델이 활동판 기록을 최대한 살려 서술하게 된다.

**(2) route.ts 삽입 지시문** — `src/app/api/generate/route.ts:278-280`
`[멘토·멘티 활동 해석]` 섹션에 "…성장 흐름으로 **자연스럽게 반영**하세요"라고 지시한다. "자연스럽게 반영"이 활동판이 유일한 소재일 때도 적극 활용하라는 신호로 작동한다.

## 4. 변경 범위 및 제약

**프롬프트 텍스트만 수정한다.** 코드 로직·타입·데이터 흐름·localStorage 스키마·컴포넌트는 변경하지 않는다.

- 기본 시스템 프롬프트(`SETEUK_DEFAULT_SYSTEM_PROMPT`)만 수정. 레거시 상수(`LEGACY_*`)와 커스텀 프롬프트 경로는 건드리지 않는다 → 커스텀 프롬프트를 쓰는 교사에게는 영향 없음.
- route.ts 지시문과 시스템 프롬프트 규칙은 서로 모순되지 않게 **같은 표현**을 쓴다.
- 프롬프트 캐시·추적 일관성을 위해 버전 상수를 bump한다.

## 6. 검증

1. **정적 검증**: `npm run lint && npm run build` (+ 가능하면 `npx tsc --noEmit`). 프롬프트 텍스트 변경이라 통과해야 정상.
   - 참고: 이 리포에는 테스트 프레임워크가 없다(`test` 스크립트 없음). 단위 테스트는 대상 아님.
2. **활동판 단독 케이스 (핵심)**: 관찰 메모·학습 데이터 없이 짝모둠 활동판 기록만 있는 학생으로 세특 생성. 출력에 조 번호("11조"), 역할("멘토"/"멘티"), 활동명("서로 알아가기"/"관계 형성")이 **없어야** 하고, "수업 활동에 꾸준히 참여함"류 일반 태도 문장이 나와야 한다.
3. **회귀 케이스**: 관찰 메모가 있는 학생으로 생성. 관찰 메모의 구체 장면이 중심이고 활동판 해석은 태도 보조로만 반영 — 기존 동작 유지 확인.

> 검증 팁: `/api/generate`는 `withTeacherAuth`로 보호되고 활동판 데이터는 클라이언트 localStorage에서 전달되므로, curl 단독보다 **로그인된 write 화면에서 생성 버튼**으로 확인하는 게 정확하다. OpenAI API 키가 없으면 fallback 템플릿이 반환되므로 키가 설정된 환경에서 확인한다.

만약 검증 후에도 활동판 언급(조/역할/활동명)이 남으면, `src/lib/prompts/seteuk.ts`의 `[표현 제한]` 목록에 "조 번호, 멘토·멘티 같은 역할명, 활동명"을 최종 출력 제외 항목으로 추가해 규칙을 강화한다.

## 8. 2026-07-10 구현 보완

코드 리뷰에서 확인된 실제 생성 경로를 반영해 원래의 프롬프트 텍스트 변경 범위를 다음처럼 보강했다.

- 단일 생성뿐 아니라 두 명 이상에서 우선 사용되는 `/api/generate-batch`에도 같은 정책을 적용한다.
- `formatObservationBoardContextForPrompt`가 조 번호, 역할명, 활동명, 날짜, 차시별 주제와 원시 △/○ 정보를 제거한 뒤 짧은 참여 태도 신호만 전달한다.
- 관찰 메모 또는 의미 있는 학습 데이터가 있으면 태도 보조 근거로, 둘 다 없으면 일반적인 수업 참여 태도 한 문장으로만 사용할 수 있게 지시한다.
- 개인 프롬프트 본문은 수정하지 않지만 전역 근거 최소화 정책은 기본/개인 프롬프트 모두에 적용한다.
- 회귀 테스트는 활동판 단독, 관찰 메모 동반, 공백 학습 데이터의 세 경우를 고정한다.
