# AI 세특 생성 규칙 기반 점검 통합 설계

**상태:** 사용자 승인 완료, 구현 계획 작성 전
**작성일:** 2026-07-14

## 배경

Seteuk의 `/write`에는 이미 `RAG 점검·개선`, 맞춤법, 금지어 기능이 따로 존재한다. `RAG 점검·개선`은 공개 학생부 지침을 검색한 뒤 AI가 세특 본문을 다시 쓰는 기능으로, 단순 검수 흐름과 목적이 다르다.

이번 변경은 기존 생기부 세특 검수 도구의 안전한 규칙 기반 검수 흐름을 AI 세특 생성 화면에 이식한다. 교사는 선택한 학생의 세특을 한 번에 점검하고, 확실한 띄어쓰기만 자동 반영하며, 맞춤법과 유의 표현은 검토 후 처리한다.

## 목표

- 세특 본문을 수정할 때마다 글자 수를 즉시 확인한다.
- 선택한 학생의 세특을 병렬로 점검한다.
- 연속 공백·전각 공백·불필요한 줄바꿈 및 맞춤법 검사에서 확정된 띄어쓰기 제안만 자동 반영한다.
- 맞춤법 제안은 교사가 확인한 뒤 적용한다.
- 기재 유의 표현은 규칙 기반으로만 표시하고 자동 수정하지 않는다.
- AI/RAG를 호출하지 않는 빠르고 예측 가능한 점검을 제공한다.

## 비범위

- `/write`에서의 AI 문장 재작성 또는 RAG 근거 검색
- 마침표·쉼표·따옴표 등 문장부호 자동 보정
- 유의 표현의 자동 삭제·치환
- 이번 점검 흐름에서 OpenAI 기반 유의 표현 판정
- 상담 화면의 `/api/record-review` 기능 변경

## 사용자 경험

### 도구막대

`AI 세특 생성` 옆에 단일 `점검` 버튼을 둔다. `/write`에서 다음 개별 버튼과 그 핸들러를 제거한다.

- `RAG 점검·개선`
- `맞춤법`
- `금지어`

`역량` 등 이 변경과 무관한 작업은 유지한다. `/api/record-review`와 상담·점검 화면은 유지한다.

### 실시간 글자 수

각 세특 본문 셀에 `글자 수 123 / 500자` 형식의 보조 정보를 표시한다. 본문 입력, AI 생성 결과 반영, 자동 띄어쓰기 반영 때 즉시 다시 계산한다. 500자를 초과하면 경고 색상으로 표시한다.

### 점검 실행과 결과

점검은 체크한 학생만 대상으로 하며, 한 번에 최대 10명을 처리한다. 선택이 없거나 본문이 비어 있는 학생은 안내에 포함하고 검사하지 않는다.

선택한 각 학생은 최대 4개 작업자 안에서 병렬 처리한다. 한 학생 안에서는 다음 순서로 처리한다.

1. 로컬 공백 정규화로 확실한 띄어쓰기만 자동 반영한다.
2. 정규화된 본문을 대상으로 맞춤법 검사와 유의 표현 검사를 동시에 실행한다.
3. 띄어쓰기 유형의 맞춤법 제안은 자동 반영하고, 맞춤법·문법 유형 제안은 검토 대기 결과로 남긴다.
4. 유의 표현은 근거·대체 방향과 함께 경고로 남기며 본문을 바꾸지 않는다.

점검이 끝나면 하나의 결과 창에서 학생별 `자동 반영된 띄어쓰기`, `확인할 맞춤법`, `유의 표현`을 묶어 보여 준다. 교사는 맞춤법 제안을 선택적으로 적용할 수 있다.

## 규칙과 API 경계

### 띄어쓰기와 맞춤법

- 확실한 공백 정규화는 브라우저/서버의 규칙 모듈에서 처리한다.
- 기존 `/api/speller` 결과 중 `spacing` 유형만 자동 적용한다.
- `spelling` 및 `grammar` 유형은 기존 수정 제안 UI를 확장해 교사가 확인하고 적용한다.
- 외부 맞춤법 서비스가 실패하면 성공·무오류로 기록하지 않는다. 로컬 규칙 기반 폴백과 실패 상태를 결과 창에 명시한다.
- 공유 Vercel 환경에서는 학생 본문이 외부 맞춤법 서비스로 전달되지 않도록 로컬 폴백을 기본으로 한다.

### 유의 표현

유의 표현은 다음 규칙을 합쳐 중복 없이 반환한다.

- `DEFAULT_FORBIDDEN_WORDS`와 교사별 사용자 금지어
- `findReferenceForbiddenTermIssues`의 상호명·영문·약어 후보
- 영문 표현, 특수기호, 점수·백분율 같은 수치 표현
- 기존 생기부 세특 검수 도구의 기재 유의 표현 규칙

`/api/forbidden`에 `includeAi?: boolean` 계약을 추가한다. 기존 호출의 기본 동작은 보존하고, 새 `/write` 점검은 반드시 `includeAi: false`를 전달한다. 따라서 새 점검에서는 `checkForbiddenExpressions`와 다른 OpenAI/RAG 경로를 호출하지 않는다.

## 오류 처리

- 학생 하나의 맞춤법 또는 유의 표현 검사만 실패해도 다른 학생의 결과는 유지한다.
- 실패한 검사는 기존 결과를 `0건`으로 덮어쓰지 않는다.
- 결과 창에는 실패 학생과 재시도 안내를 보여 준다.
- 자동 반영으로 본문이 바뀌면 해당 학생의 최신 본문을 기준으로 검사 수와 상태를 갱신한다.

## 검증 기준

- 글자 수는 입력·AI 생성·자동 공백 보정 뒤 즉시 갱신된다.
- 500자 초과가 즉시 구분되어 보인다.
- 선택한 여러 학생에서 점검이 병렬 실행된다.
- 자동 공백 보정만 본문에 즉시 반영되고 문장부호는 바뀌지 않는다.
- 맞춤법 제안은 확인 전 본문을 바꾸지 않는다.
- 유의 표현은 규칙 기반 결과만 표시하며 AI/RAG 요청이 발생하지 않는다.
- 한 요청 실패가 전체 점검 성공으로 오인되지 않는다.
- `npx tsc --noEmit`, 관련 단위 테스트, 로컬 `/write` 화면·API 점검을 통과한다.
